\chapter{Development Rules}
\section{Architecture Rules}
\begin{itemize}
\item Preserve existing feature boundaries.
\item Use typed domain models and schemas.
\item Keep business rules in services/rules, not presentation components.
\item Enforce permissions server-side.
\item Preserve tenant scoping in every read/write operation.
\item Do not implement future phases inside current-phase work.
\end{itemize}

\section{Frontend Rules}
Use existing UI primitives, semantic HTML, focus-visible outlines, responsive layouts, and dark-mode tokens. Avoid introducing a second design system.

\section{Validation Rules}
Runtime validation uses Zod schemas where implemented. TypeScript types are not a substitute for runtime validation.

\section{Definition of Done}
Relevant changes should pass TypeScript, ESLint, production build, and \texttt{git diff --check}. Browser/route QA should only be claimed when actually performed.
